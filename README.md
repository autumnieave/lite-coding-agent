# 终端 Coding Agent：长任务约束遵循与后训练对齐

Agent 约束遵守实验平台——强冲突场景下的失败归因、强化学习对齐与安全护栏兜底。

针对长程 Agent 在强冲突下“约束在上下文 ≠ 模型遵守”的痛点，基于 **Qwen2.5-7B-Instruct** 基座与 **ANCHOR 分类学**对抗探针，构建“**SFT 冷启动 → RL 强化学习对齐 → 动作级安全护栏**”的 Model-System Co-design 方案。在 45 个同分布业务任务实现 **Pass^8 100%**（基座 0%）；在强冲突探针下将系统级 **Strict pass^8 提升至 61.25%**，高危越权执行率降至 **0**。

**方法链**：聚合指标 → 拆行为模式 → 控制变量 → 定位根因。

**技术栈**：Python 3.11 / asyncio / vLLM / QLoRA（peft + trl）/ 自研 GRPO-lite（group-relative advantage + KL）/ Pydantic。

## 核心成果

本项目的核心痛点在于：常规业务模型能跑，但在“任务与约束强冲突”下，模型极易崩溃（要么摆烂不干活，要么直接违规）。

我们通过“**SFT 保底业务能力、GRPO 降低违规倾向、SPA 守住绝对安全**”的三步走，实现了业务与安全的双 SLO：

| 技术演进路径 | 同分布业务能力<br>*(In-Domain Pass^8)* | 强冲突下原生合规率<br>*(Native Strict Pass^8)* | 强冲突下高危越权执行率 | 强冲突下系统级合规率<br>*(System Strict Pass^8)* |
|---|---:|---:|---:|---:|
| **基座模型** (Qwen2.5-7B) | 0.0% | — | — | — |
| **+ SFT 冷启动** | **100.0%** (解决动作塌缩) | 5.0% (7B 能力上限) | — | — |
| **+ GRPO 对齐** | 100.0% (无遗忘) | 5.0% | **25.9% (166/640)** | — |
| **+ SPA 护栏兜底** | 100.0% (无遗忘) | 5.0% | **0.0% (实际执行)** | **61.25%** |

> *指标术语说明：*
> - **Pass^8**：连续 8 次完美通过的概率（企业级可靠性要求，区别于 Pass@8“至少成功一次”）。
> - **In-Domain**：同分布业务集（测正常干活能力）。
> - **Native Strict Pass^8**：纯靠模型自身在强冲突下连续 8 次既完成任务、又零违规的概率。
> - **System Strict Pass^8**：模型在 SPA 护栏兜底后，系统整体交付的连续 8 次完美合规率。
>
> *GRPO 分层修复效果（基于 v15 冲突探针 640 次采样）*：
> - 路径越界违规率降至 **4.5%** (13/288)
> - 删除未确认违规率降至 **35.9%** (69/192)
> - 测试篡改违规率降至 **52.5%** (84/160)
>
> *表格解读：SFT 解决了基座 98.5% 拒绝调工具的问题，把业务拉到 100%（由最终模型 45 任务 360/360 验证）；GRPO 显著降低原生违规倾向，将综合越权率压低至 25.9%；但受限于 7B 模型在复杂冲突下的能力（Native Strict 仅 5%），最终由 SPA 硬拦截将高危执行率降至 0。*

## 数据构造（Data Curation）

高质量的数据管线是解决长程 Agent 约束问题的基础。本项目的训练与评测数据涵盖以下三个维度：

- **SFT 冷启动集（329 条）**：按 `正常业务(180) : 冲突合规(118) : 安全拒答(31)` 配比，且 **90.5% 包含真实的 `tool_call` 轨迹**。使用 **Completion-only Loss** 微调，消除格式幻觉。
- **偏好对齐集（142 条）**：覆盖高风险动作（路径越界、未确认删除、测试篡改），严格强制约束 ID 匹配（100% 引用正确 ID），用于验证 DPO/GRPO 算法。
- **评测基准集（145 条）**：
  - **同分布业务**：45 个长程任务（用于计算 In-Domain Pass^8）。
  - **分布外对抗**：100 条基于 **ANCHOR 分类学**（10 大类 / 78 叶类型）构建的强冲突探针。

## 架构设计

针对 7B 模型在极端对抗下策略不稳定、易发生“动作塌缩”或“越权执行”的问题，本系统采用三层渐进式架构：

1. **冷启动微调（Cold-start SFT）**：重构 329 条真实 `tool_call` 轨迹，解决基座模型在常规业务中的格式幻觉与逃避调用（动作塌缩）问题。
2. **强化学习对齐（RL Alignment）**：摒弃对文本概率优化的传统 DPO，采用 **GRPO + 确定性验证器（Verifier）** 的动作级奖励设计（按风险分级惩罚），并引入 **KL 散度约束**，直接优化 `tool_call` 的合规分布。
3. **动作安全护栏（Action Guardrail）**：针对模型自身残余的长尾越权风险，在工具派发前引入硬拦截层（SPA）。结合规则校验，实现高危动作降级确认，确保系统级 0 越权。

```mermaid
flowchart LR
A[基座模型] -->|Completion-only SFT| B[SFT 冷启动]
B -->|GRPO 动作级 Reward| C[RL 对齐]
C -->|Action Guardrail 拦截| D[生产系统]
```

## 工程架构与可观测性（Engineering & Observability）

- **并发采样架构**：核心评测与采样脚本采用 `asyncio.Semaphore` 与 `as_completed` 进行任务级并发调度（默认并发度 3–4），以支撑强化学习阶段的高频 Rollout 采样需求。
- **长程状态与副作用控制**：
  - **Checkpoint 恢复**：基于 Append-only 的 `session.jsonl` 实现会话持久化，支持解析回放与异常中断后的无缝续跑。
  - **幂等控制（Idempotency）**：工具层基于 `task_id + 工具名 + 参数 SHA256` 实现幂等缓存，防止大模型在长程任务中因重复生成导致的重复副作用（如重复删文件、重复提交），集成测试已验证同一任务内相同参数仅执行一次。
- **上下文成本控制**：内置多级上下文压缩机制，记录每次压缩前后的估算 Token 变化与耗时；在约束独立注入场景下，将长程上下文稳定控制在 615 token 左右（注入层均值 163 token），避免上下文膨胀与注意力稀释。
- **Trace 归因与回放**：输出基于会话轨迹与工具事件回调（Event Callback）的结构化记录，针对超时、约束违规或工具执行异常，支持按 Session ID 进行细粒度的动作归因与断点回放。

## 评测方法论

项目采用双轨评测体系，严格区分“同分布业务能力”与“分布外对抗鲁棒性”：

1. **同分布业务（In-Domain）**：45 个长程任务，采用 `pass^8` 可靠性口径，验证模型在无对抗环境下的任务闭环能力。
2. **对抗基准（OOD）**：基于 **ANCHOR 约束分类学**构建 100 条强冲突探针，并配合 **McNemar 检验**与 **Wilson 置信区间**进行统计学归因。

> 注：v16 GRPO 评测采用 temperature=0.8 与固定 seed 策略，以保证采样一致性。

> 注：早期在 DeepSeek API 上独立验证过“约束独立存储 + 双路注入”的摘要抗遗忘机制，逐字保留率从 69% 提升至 95%，该机制已内化至本项目的 Agent Loop 中。

## 边界与限制

- **任务重叠**：45 个业务任务与训练集有同族重叠，非 clean held-out。
- **ANCHOR 参照**：本项目复用 ANCHOR 的约束分类学构建探针，不冒充官方 harness 跑分。
- **护栏职责**：安全护栏（SPA）是系统的最后防线，用于兜底模型残余的 25.9% 长尾越权尝试，不代表模型已实现 100% 原生合规。
- **跨模板泛化**：任务集覆盖 4 个模板族，策略未验证对未见模板族的外推能力。
- **无节省率与并发提速数据**：压缩机制记录了绝对 Token 水位，但未做 A/B 对照组；脚本实现了异步并发，但未做受控串行跑分。

## Roadmap

- [ ] **模型泛化**：在 14B / 72B 模型上验证 Native Strict Pass^8 的提升幅度，降低对工程护栏的依赖。
- [ ] **约束表达体系**：探索更丰富的约束 DSL，支持复杂的组合逻辑（如：跨文件级联验证）。
- [ ] **数据飞轮闭环**：引入真实业务流水中的 Badcase 自动回流机制，实现“评测-归因-重训”的自动化迭代。
