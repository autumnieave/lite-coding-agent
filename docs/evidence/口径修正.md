## 1. 问题 1：19 → 5 的来源

### 1.1 代码路径

- `scripts/constraint_experiment.py:255-263` 的 `judge()` 只有三个脚本化检查：
  `json_valid`、`snake_case_keys`、`no_code_fence`。
- `scripts/constraint_experiment.py:461` 把它写成
  `"violated": sum(1 for ok in checks.values() if not ok)`。
- `scripts/constraint_experiment.py:497` 在汇总表里对所有 run 的
  `violated` 求和。
- 对 `src/` 全文检索 `path_escape_triggered` 与
  `blocked_by_constraint`，**没有命中**；`src/agent/tools/base.py:122`
  只在单次工具调用越界时返回结构化结果 `error_kind="path_escape"`，没有累计
  到压力档实验的 `violated`。

### 1.2 19 / 5 的可复核算术

来源是两次修复后压力档复跑，每组 10 次：

| 文件 | off `violated` | on `violated` |
| --- | ---: | ---: |
| `docs/evidence/stress_after_fix_runs.jsonl` | 11 | 2 |
| `docs/evidence/constraint_retention_stress_rerun.jsonl` | 8 | 3 |
| 合计 | **19** | **5** |

因此 19 → 5 是 **judge 行为探针失败项计数**，不是文件路径越界拦截次数，也不是
`ConstraintStore` 的补录次数。

### 1.3 简历应采用标签

用：

> 约束压力探针中 3 项脚本化输出检查的失败数：关闭机制 19 → 开启 5（judge 判定）

不要用：

- “路径越界拦截 19 次”
- “约束拦截 19 次”
- “19 次真实副作用”

层级：**行为/判定层（judge）**；不是执行前拦截层。

### 2.1 标注边界

- `+50.3pp` 与 `99.8%` 只能绑定 train-v6 adapter；不能写成 train-v5 或 train-v4 的增益。
- 会话约束、GRPO、DPO 只能绑定 train-v5 adapter；其中 DPO 的最终产物是另一个
  DPO adapter，不能拿 DPO 产物的 SHA 当 SFT adapter。
- train-v6 的 45/45 任务仍有同族训练样本，因此 clean held-out 的结论限定为
  **同族实例泛化**，不是跨模板泛化。
