# 冲突专项：run 2 / event=44 的互斥约束与失败路径

## 范围与证据

- 对象：`private/traces/constraint_experiment/stress/on/stress_run02_rollout02.jsonl`
  的 `event=44`（`step_label=probe_json`）。
- 采样：`temperature=0.0`、`top_p=None`、`seed=20261019`；模型
  `deepseek-flash`，`system_fingerprint=e72d3c7f663d3e1383b00b3884cb4501`。
- 证据边界：只读本仓库 trace；不跨项目取材。完整 messages、response、约束位置均来自
  该事件，不用 `reply_head` 代替。

## 问题一：两组约束的原文与出现位置

两组共 12 条约束都在当轮实际发送的 `message[1]`（`role=system`）的
`[历史对话摘要]` 中，属于“四、关键约束”一节。trace 的逐条字段为：

```text
locations = ["summary"]
in_summary = true
declaration_message_present = false
in_replenish = false
compressed_out_of_history = false
content_in_messages = true
model_saw = true
```

因此它们**不在**基础 system prompt（`message[0]`），**不是**压缩后的按 id 补录，
也**不是**被压缩替代；它们就在当轮 messages 的历史摘要里，模型确实看得到。

## 问题二：模型原话与最终输出结构

模型在 JSON 的 `unresolved_conflicts` 中写道：

> `log_prefix`：`status: unresolved_conflict`，`candidates: [EQGMZE, LP4G2B, PSZYAU,`
> `SVVP7J, XCFFA2, ZRNSRP]`，`reason: 六个约束要求互不相同的日志前缀，无法同时满足；`
> `本次输出未产生日志行，故未套用任何前缀。`

> `timestamp_format`：`status: unresolved_conflict`，`candidates: [EU5C3E, NHRDLU,`
> `Q23MJP, UFHH6K, XPT8JQ, ZS65PL]`，`reason: 六个约束要求互不相同的时间戳写法，`
> `无法同时满足；当前仅按 D24PBJ 采用 UTC 的 ISO 8601 形式，需用户裁决后替换。`

JSON 结构本身是完整的：

- 顶层 18 个键，均为 snake_case；
- `constraint_codes` 有 40 项，覆盖 40 条约束；
- 7 个 `field_*` 键齐全；
- `unresolved_conflicts` 是对象，含 `log_prefix` 与 `timestamp_format` 两个条目；
- 主体 JSON 在追加说明前可以独立解析。

JSON 结束后，模型又追加了一段自然语言：

> “上面的两个 conflict 项就是本次无法同时满足全部硬性约束的原因，其余约束（合法 JSON、
> 无代码围栏、snake_case 键名、无 emoji、无制表符、路径正斜杠、列表按字母序、
> 七个必填字段齐全）均已满足。”

这段追加文本使整条回复不能被 `json.loads` 解析，因此 `json_valid=false`；
`snake_case_keys` 也随之失败。**直接失败点是 JSON 尾部追加说明，而不是 JSON 内部缺少
冲突表达。**

## 问题三：失败是“冲突导致必须解释”，还是“模型选择追加解释”

结论：**冲突真实存在，但当前证据不足以把格式失败归因为“冲突导致模型必须解释”。**

依据：

1. JSON 内部已有结构化的 `unresolved_conflicts`，可以完整表达两组冲突；协议没有要求
   在 JSON 之后再写自然语言。
2. 直接失败点是尾部追加文本；去掉这段文本，JSON 主体本身合法且键名符合 snake_case。
3. 受控冲突实验（4 组 × 5 次，固定采样配置，单轮 probe）显示：

| 组 | 类型 | 非空 `unresolved_conflicts` | `conflict_resolution` | 输出格式失败 |
| --- | --- | ---: | ---: | ---: |
| `weak_compatible` | 弱（可同时满足） | 0/5 | 0/5 | 0/5 |
| `weak_independent` | 弱（不同槽位） | 0/5 | 0/5 | 0/5 |
| `medium_priority` | 中（有优先级，需取舍） | 1/5 | 5/5 | 0/5 |
| `strong_mutual_exclusion` | 强（同槽位互斥） | 5/5 | 0/5 | 0/5 |

逐次 trace：`private/traces/conflict_intensity/<group>/rollout00-04.jsonl`；
汇总：`private/traces/conflict_intensity_runs.jsonl`。该目录属于受控实验，不并入主样本
或负对照统计。

强冲突组 5/5 都识别出 `unresolved_conflict`，但没有一次因为冲突而稳定产生输出格式失败；
弱冲突组也没有。因此“强冲突 → 稳定格式失败”的受控证据不成立。

可观察行为更符合这样的描述：**模型识别到冲突后，选择了在 JSON 之后追加解释**。这是
对输出行为的描述，不对模型主观意图下结论。

## 对归因表的影响

- `约束是否冲突` 仍记为“是”，因为两组原文确实同时出现在当轮 messages 中；
- 根因分类保持 `sampling_noise`，不改为“能力问题（多约束冲突）”；
- CSV 备注写明：冲突真实、直接失败原因是尾部追加说明、受控实验未复现稳定格式失败、
  能力问题证据不足；证据指向 `docs/evidence/冲突专项.md,event=44`。

这与预注册规则一致：行为问题需要“原文在当轮 messages + 工具参数合法 + stable 违反”；
`event=44` 在 10 次 rollout 中只命中 1 次，属于 `intermittent`，不能升级为能力问题。

## 判定器修正后复核（2026-10-19）

**复核边界**：不跑新实验，不调用模型。只读取现有 20 条受控冲突 trace
（`private/traces/conflict_intensity/<group>/rollout00-04.jsonl`）和 110 次难度调参正式重跑
（`private/difficulty_tuning/runs.jsonl`），按修正后的判定器重新统计。

### 复核口径

- `unresolved_nonempty`：严格从当轮 `llm_turn.response.content` 解析 JSON，且
  `unresolved_conflict` / `unresolved_conflicts` 的值为非空。它不是“回复里出现过冲突字样”。
- `format_failure`：`json_valid=false` 或 `snake_case_keys=false`；不由 `reply_head` 判定。
- 110 次重跑中的 `conflict_declared`：使用修正后的显式声明词表（包含“互斥 / 不可能同时 /
  不能同时满足”），只适用于该任务的自然语言回复判定，不等同于受控 trace 的结构化
  `unresolved_nonempty`。

逐条结果见 `docs/evidence/冲突专项_复核.csv`。

### 复核结果

| 组 | 非空 `unresolved_conflicts` | `json_valid` | 输出格式失败 |
| --- | ---: | ---: | ---: |
| `weak_compatible` | 0/5 | 5/5 | 0/5 |
| `weak_independent` | 0/5 | 5/5 | 0/5 |
| `medium_priority` | 1/5 | 5/5 | 0/5 |
| `strong_mutual_exclusion` | 5/5 | 5/5 | 0/5 |

110 次正式重跑中，`U-TUNE-CONFLICT-STRONG` 的 `conflict_declared` 从首轮的 `9/10`
修正为 `10/10`；这不是受控 trace 的结构化 `unresolved_nonempty` 从 5/5 上升，而是
自然语言声明判定的一个假阴性被消除。强冲突的结构化命中率原本已是 5/5，修正后没有上升；
受控格式失败仍为 0/5。

`private/traces/conflict_intensity_runs.jsonl` 中部分 `unresolved_conflict` 布尔值与
逐条 trace 不一致（例如弱冲突组被标成 true），该汇总文件不能作为最终证据；本次复核
只使用 trace 原文重判，并把它记录为已知陈旧汇总字段。

### 复核结论

**判定器修正未改变结论。** 强冲突被模型稳定识别，但没有稳定导致输出格式失败；直接失败点
仍是 JSON 主体之后追加自然语言，而不是“冲突使模型无法输出合法 JSON”。因此：

- 不把该检查项从 `sampling_noise` 升级为“能力问题（多约束冲突）”；
- 不把 110 次中的 `10/10` 声明误写成“10/10 格式失败”；
- 受控冲突实验只作为能力边界的描述性证据，不并入主样本或负对照统计。
