# 简历措辞：终端 Coding Agent

**终端 Coding Agent：长任务约束遵循与后训练可靠性验证** | 个人项目
github.com/autumnieave/lite-coding-agent

项目概述：针对长任务中压缩静默丢失约束、且“约束在上下文≠模型遵守”的痛点，独立构建终端 Coding Agent 实验平台，诊断约束遵守的失败模式并归因到训练信号质量——聚合指标会掩盖问题，拆到行为模式才能诊断、再控制变量定位根因；方法在 64 条探针上验证稳定性。验证规模：409 唯一任务池、45 任务配对评测。

技术栈：后训练（SFT/QLoRA/Loss Masking）· 评测（Trace 归因/pass^10 / 稳定通过率/McNemar/预注册门槛）· Agent（Harness Engineering/Guardrails/Context Engineering）· 工程（vLLM/pytest 857/CI）

约束层（Guardrails + Context Engineering）：原文在 ≠ 行为生效。自研约束独立存储 + 双路注入 + 约束补录，压力档（deepseek-flash）违规 19→5 次、原文保留 69%→95%；但 Qwen2.5-7B 基座在 32 条约束探针上仅 12/32 合规，train-v5 SFT 为 11/32、train-v6 SFT 为 28/32（小样本、方向性）。补录已由仅校验 ID 改为 ID+正文，但 untagged 模式不创建 ConstraintStore，修复效果未验证——系统侧可保证原文完整性，行为生效需训练侧补。

工具层（Harness Engineering）：能调用 ≠ 调用可靠。从零实现 Tool-Calling Agent Loop + 6 工具（Pydantic 参数校验 + 路径越界拦截），补幂等键防重复副作用、会话 checkpoint 支持 kill 后恢复。

评测层（Trace 归因）：模型能跑 ≠ 结果可信。全链路 Trace 归因发现 temperature=0 下仍有 3.57% 判定翻转率（560 配对观测），引入 pass^10 / 稳定通过率口径；在去重叠的 45 个任务上，SFT 提升 +50.3pp（McNemar p<1e-13），重叠/非重叠增益一致，排除逐字记忆。

训练层（SFT 变量归因）：能训 ≠ 训对了。Loss Masking 单变量对照：full-loss 长上下文任务 0/10、assistant-only 恢复 10/10——算法是必要条件。诊断方法：聚合指标 → 拆失败模式 → 唯一变量对照 → 定位根因——旧 32 条实验中 train-v5 SFT 合规 11/32 < baseline 12/32，聚合指标看是负收益；拆失败模式发现违反仅 1、只读 20——不是“没学会遵守”，是“学会了只读最安全”；同算法同模型、唯一变量是 train-v6 移除 67 条中间态轨迹，合规升至 28/32——定位到训练信号确定性（歧义样本导致退化解），而非算法选择。稳定性验证：扩到 64 条探针后，train-v6 合规 53/64；同批 64 条中 train-v5 20/64 < baseline 24/64，方向与旧口径一致，32 条高估约 4.7pp。边界：补录修复在 tagged 路径可达、untagged 不创建 ConstraintStore——系统侧修复与行为层改善是两条路径，不能假设修了补录就能改善行为（64 条探针、训练重叠池、未做显著性检验）。

决策层（GRPO 预检）：能启动 ≠ 该启动。GRPO 预检——45 任务 × 8 rollout，44/45 饱和、存在部分成功/中间态信号的任务为 0，按预注册判据（中间态为 0 则不启动），SFT 已覆盖这批任务、RL 无梯度信号，因此不启动全量 RL。
