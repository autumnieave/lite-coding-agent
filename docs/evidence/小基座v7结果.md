## 1. CTX 修复

v7 的 20 条 error 全部是：

```text
This model's maximum context length is 4096 tokens.
However, your request has 4575 input tokens.
```

根因不是 fixture 写错，而是 `context_recall` fixture 每个文件 180 行，`CTX-HARD` 还要读
10 个文件；即使只看第一轮，读一个文件后的请求就已经超过 4096。修复做了两项：

1. fixture 从 180 行/文件缩到 25 行/文件（`CONTEXT_LINES_PER_FILE=25`）；
2. vLLM `--max-model-len` 从 4096 提到 8192。

v8 只重跑 CTX 两任务、各 10 次；结果是 **20/20 有效、0 个 400 error**，说明 400 已消失，
且不是把 error 当成违反统计。

判断：20 个 stable **不是集中在 1–2 个任务**，而是分布在 7 个任务、4 个维度。
`constraint_count` 10 项、`context_length` 2 项、`tool_parameters` 3 项、`conflict` 5 项，
`check_depth` 为 0。格式失败（fenced JSON）跨 `C1-BASE` / `C1-HARD` / `TOOL-BASE` 重复；
行为失败独立出现在 `CTX-HARD`、`TOOL-HARD`、`CONFLICT-WEAK`、`CONFLICT-STRONG`。
因此应写“行为问题跨任务稳定”，同时把格式问题和行为问题分开报告。

v7 原 18 个 stable 的分布是：`C1-BASE` 5、`C1-HARD` 5、`TOOL-BASE` 2、
`TOOL-HARD` 1、`CONFLICT-WEAK` 3、`CONFLICT-STRONG` 2；CTX 重跑后新增
`CTX-HARD` 2，合计 20。`TOOL-HARD` 已人工复核：10/10 读取正确路径
（`part03.txt`、`part07.txt`），参数合法、无越界，工具结果 7 + 9 = 16；模型 10/10
回复 `{total_lines: 18}`，属于行为/算术错误，不是 fixture 或工具参数问题。

## 5. 证据解释

1. **协议层已经通过**：`tool_calls` 非空，`read_file` 参数合法，`tools_used` 与
   `params_ok` 在工具任务上为真。因此 C1 / TOOL-BASE 的 `json_valid`、`no_fence`
   稳定失败不是工具协议或路径校验失败，而是模型把最终输出包进 Markdown fence。
2. **存在真正的行为层 stable 违反**：
   - `CTX-HARD`：只读 2/10 文件，最终答错；长上下文多轮指令遵循失败。
   - `TOOL-HARD`：读取正确两个文件，但 `total_lines=18`，期望 16；算术错误。
   - `CONFLICT-WEAK`：约束要求小写文件名，用户请求 `Report.txt`；模型直接写大写文件。
   - `CONFLICT-STRONG`：两条约束互斥；模型直接写 `target.txt`，未声明冲突。
3. **格式与行为要分开**：`C1-BASE` / `C1-HARD` / `TOOL-BASE` 的 stable 是 fenced JSON
   造成的格式失败；`CTX-HARD` / `TOOL-HARD` / `CONFLICT-*` 是行为或语义失败。不能把
   20 个 stable 都写成“模型能力不足”，也不能都写成“格式问题”。
4. **与历史结论的关系**：`deepseek-flash` 的 dev/test stable=0 仍成立，但不能外推到 1.5B。
   1.5B 在相同任务分布上已出现 20 个 stable，其中 8 个是行为/语义检查。

## 6. 门禁判断

按预注册规则（同一检查项 10 次 rollout 命中 ≥6 次为 stable）：

- `constraint_count`：10 个 stable，达到门禁；
- `context_length`：2 个 stable，达到门禁；
- `tool_parameters`：3 个 stable，达到门禁；
- `conflict`：5 个 stable，达到门禁；
- `check_depth`：0 个 stable。

五个维度中四个出现 stable，合计 20 个检查项、7 个任务。路线 B 的任务分布重构有实测依据；
但本轮仍是 dev-only ladder，不是最终 test，也没有跑四组对比或 SFT。
