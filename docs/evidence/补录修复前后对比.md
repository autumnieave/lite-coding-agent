**日期**：2026-10-28  
**范围**：8 个中间态任务 × 2 类约束 × 2 种注入方式 = 每个条件 32 条；
baseline 与 SFT 各 32 条，合计 64 条观测。  
**定位**：方向性证据；不写“修复成功”，也不把本轮未触发当成“修复失败”。

**更正（2026-10-28）**：本文记录的是自然摘要实验，修复前后均未触发补录，因此结果不变。
后续已补 tagged 故障注入（强制 ID-only 摘要）64 条，验证补录路径：语义保留
`0/64→64/64`、合规 `17/64→64/64`。详见
[补录修复_tagged模式重测.md](补录修复_tagged模式重测.md)；本文不作为“修复无效”的证据。

## 1. 修复内容

`ensure_constraints` 原先只通过 `ConstraintStore.verify()` 检查 ID 是否还在摘要里。
本次在 `src/agent/core/constraints.py` 增加 `require_body` 校验：ID 在且正文在
才算保留；ID 在但正文缺失时标记为 missing。`src/agent/core/compaction.py`
的 `ensure_constraints` 改为调用 `verify(summary, require_body=True)`。

正文比较忽略空白差异，不做语义等价判断；改写或只保留 ID 都会触发补录。
新增单测覆盖三种情况：ID 在正文丢、ID 在正文在、ID 不在。全量测试结果：
`860 passed, 1 skipped, 37 deselected`；`ruff check .` 与
`ruff format --check .` 均通过。

## 4. 调用链检查（为什么不提升）

探针的 `run_condition` 只在 `mode == "tagged"` 时创建 `ConstraintStore`：

```python
store = ConstraintStore() if mode == "tagged" else None
compactor = Compactor(config, summarize=summarize, constraints=store)
```

`ensure_constraints` 在 `self._constraints is None` 时直接返回：

```python
if self._constraints is None:
    return summary, 0
```

本轮唯一的语义丢失是 SFT untagged 的 `PUB-XLAM-00071` 行为约束
`BVQ4HP`；该模式没有 `ConstraintStore`，`ensure_constraints` 不会被调用。
tagged 模式的 16/16 条正文原本就在，没有 missing，补录也不会发生。
因此修复后的语义保留、合规、违反均不变。

## 5. 判定

**本文自然摘要实验呈现为“语义保留不变”，当时不能据此写“修复未生效”或“修复成功”。**
调用链检查表明：修复代码已进入 kernel bundle，单测也覆盖了 ID-only 触发补录；
只是本轮 64 条探针的唯一丢失落在无 store 的 untagged 模式，修复路径不可达。
这是探针覆盖缺口，不是 `ensure_constraints` 调用链断裂。

为验证行为收益，后续新增了 tagged 模式下强制摘要丢掉正文的探针，结果见
[补录修复_tagged模式重测.md](补录修复_tagged模式重测.md)；本文结果不据此外推为
“补录修复无效”。
