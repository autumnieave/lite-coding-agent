## 2. Qwen tokenizer 门禁（本地真实 tokenizer）

使用本机缓存的 Qwen2.5-7B-Instruct tokenizer 对 train-v4 执行
`training.validate_train_v4 --max-length 3072`：

- train：380 行，结构失败 0，assistant mask 失败 0，超长 19 行；
- val：80 行，结构失败 0，assistant mask 失败 0，超长 6 行；
- token 数 p50：train 1678、val 1676；最大 6900；
- 训练脚本会显式丢弃超长行并写入 manifest，实际预期 train 361 / val 74；
- 超长行集中在 CTX-HARD 的 oracle 克隆（6444 token）和 DeepSeek 长轨迹，
  因此 CTX 的有效训练行数会从 47 降到约 28，报告 CTX 结果时必须写清。

门禁首次运行时发现 3 条 DeepSeek 轨迹的 assistant 消息同时含 `content` 和
`tool_calls`，被项目自定义校验器拒绝。用 Qwen tokenizer 直接渲染这些轨迹成功、
`check_rendered_text` 无失败；因此根因是校验器过严，不是数据或模板不兼容。
已移除“tool_calls 消息不得含 content”的限制，train-v4 字节未改动、SHA 不变。

## 3. 训练代码修复

### 3.1 assistant-only 的 labels 会被默认 collator 覆盖

TRL 0.12.2 在数据集已含 `input_ids` 时原样使用数据集，但默认
`DataCollatorForLanguageModeling(mlm=False)` 会重新用 `input_ids` 生成 `labels`。
这会让 assistant-only 实验静默退化成 full-loss，变量实际上没有改变。

修复：新增 `training.loss_masking.LabelPreservingCollator`，只做 padding，保留
调用方提供的 `labels`；`train_sft.py` 仅在 `assistant_only` 模式注入该 collator。
新增单测覆盖 label 保留和长度不一致拒绝。

数据侧核对：用同一 Qwen tokenizer 对 train-v4 的 380 行计算 assistant-only 掩码，
平均只保留 **5.09%** 的 token（中位数 75 / 1678），即 system、user、tool result
全部为 `-100`。这说明 assistant-only 与 full loss 不是近似配置；如果默认 collator
未被替换，两者会变成完全相同，因此该修复是对照成立的前置条件。

第一次 assistant-only 运行还暴露了第二个变量污染：`tokenize_training_row` 先截断
再返回 `token_count`，导致 19 条超长 CTX 行没有被过滤（日志为 94 step / 380 行），
而 baseline 是 90 step / 361 行。这会把“loss masking”与“多保留 19 条长样本”混在
一起，不能作为单变量对照。该次运行已作废并删除，未采用其任何指标。

修复：assistant-only 现在先统计完整序列 token 数，再截断并构造 labels；`token_count`
保留完整长度，训练前的过滤器与 full-loss 使用同一口径。本地复算确认 380 行中
19 行超长、361 行进入训练，与 baseline 的 90 step 对齐。若截断把 assistant 段切掉，
labels 置为全 `-100` 占位，随后由超长过滤丢弃，不会静默训练空目标。

### 3.2 mix15 的 CLI 参数与 kernel 调用不一致

`build_method_kernel.py` 传入 `--general-file` / `--out-file`，但 `data_mix.py`
只接受 `--mixed-out`，且会强制从本地 Dolly 原始文件重建通用数据。mix15 kernel
会在训练前直接失败。

修复：`data_mix.py` 支持复用已有 general JSONL，并为 `--mixed-out` 增加
`--out-file` 别名。用 kernel 的实际参数本地重跑，输出 447 行、SHA 与冻结的
`train_mix15.jsonl` 完全一致（`190c635d...`）。

### 3.3 DPO 摘要取错 adapter 目录

DPO 实验实际 adapter 在 `dpo_adapter/`，摘要却读取 `adapter/`，会把
`adapter_sha256` 写成 `null`、`adapter_bytes` 写成 0。已改为按实验选择摘要目录，
并在生成的 `run.py` 中核对。
