## 1. 两条路线

### 路线 A：停在诊断 + 评测方法论 + 训练管线储备

不构造统一数据集，不跑 7B 训练。保留：

- benchmark 回归基线；
- 约束违反归因、trace schema、稳定性门禁；
- 方向 C 的手工自检和 constrained decoding 对照；
- `training/` 下的 SFT/GRPO 配置与 reward 骨架，但标记为“工程储备、未启动”。

结论写法：

> 现有 benchmark 不适合训练，主样本 stable=0；训练分支未启动。

### 路线 B：构造统一数据集，做四组 test 对比

按 `docs/evidence/统一数据集方案.md` 构造新的任务实例，覆盖难度、上下文长度、语义/工具检查、步数预算和完整轨迹。先 pilot dev/test，再扩到 100–200 个任务；在同一 test set 上比较：

1. baseline；
2. +系统侧；
3. +训练；
4. +系统侧+训练。

结论写法：

> 系统侧与训练侧各自在 test 上带来多少约束遵守率、工具调用成功率和任务完成率变化；谁负责哪种错误。

增益按 `B−A`（系统侧）、`C−A`（训练侧）、`D−A`（组合）和 `D−B−C+A`（交互）拆分；如果系统侧已把格式违反压到 0，而训练侧没有在工具行为/语义检查上带来额外增量，结论应写“训练不必要”，不能把格式收益改写成训练收益。

## 2. 成本与结论强度

| 维度 | 路线 A | 路线 B |
| --- | --- | --- |
| 数据成本 | 不新增训练任务；只维护回归与归因 | 100–200 个任务的夹具、检查器、完整轨迹和 split；预计 5–10 个工程日量级 |
| GPU/训练成本 | 0；只做本地评测与文档 | Kaggle T4 上 QLoRA SFT 与评测；预计数小时 GPU 时间，另加失败重跑 |
| 评测成本 | 低；复用现有 benchmark 与 trace | 四组 × test manifest × 10 rollouts；本地或云端都要真实执行 |
| 结论强度 | 对“现有 benchmark 不适合训练”很强；对训练增益没有证据 | 若 stable 违反率和样本量足够，可分离系统侧/训练侧增益；若 stable 仍为 0，只能得到空结论 |
| 主要风险 | 容易被误解为“没做训练” | 任务构造偏差、test 泄漏、stable 不足，导致四组对比没有统计意义 |
| 简历价值 | 诊断、评测方法论、可复现实验、训练管线储备 | 数据构造、系统加固、训练工程、消融与误差归因；但必须有真实结果才成立 |

## 3. 进入路线 B 的前置门禁

在生成 train 前必须先满足：

1. dev/test pilot 的 baseline 各有至少一个任务出现 stable 违反（10 次 rollout 中同一检查项命中 ≥6 次），且不是靠改采样配置凑出；
2. 至少覆盖一个语义/工具行为违反，而不是只有 `json_valid` 这类格式问题；
3. constrained decoding 与手工自检的结果能说明系统侧已经覆盖了什么，避免把系统侧能解决的问题重复拿去训练；
4. 最终 test manifest 在四组运行前冻结并记录哈希，四组只跑一次，不再调任务或 prompt；当前 7+7 pilot test 曾受 U-T01 检查器修正和 U-D07/T07 补入影响，不能直接充当最终 held-out。

若第 1 条不满足，优先调任务难度和上下文长度，不调 temperature/top_p/seed；若仍为 0，停留在路线 A，不为了“进入训练”而降低门禁。

## 4. 建议（v2，待确认）

### 4.1 当前能下的结论

- 在 `deepseek-flash` 上，统一数据集 dev/test 和五维难度阶梯都没有 stable 违反；110 次调参的 hard 组最高只有 4/10。路线 B 的“至少一个 stable 违反”门禁在当前基座上未满足。
- 两轮相同配置的观测翻转率为 3.57%，说明 temperature=0 下仍有 API 侧非确定性；不能把单轮 4/10 或 0/10 写成稳定能力。
- 当前 pilot test 仍然只是调参用，不是最终 held-out；最终 test 已另行冻结为 `final-test-v1`（SHA-256 `ef4d3113...653af7`），并完成 110 条 baseline；但 U-FT10/11 的 prompt/fixture 不一致，6 个 stable 不能归因给模型。
- 小基座 Coder-1.5B 因 Hermes 协议不匹配未进入 ladder；`Qwen2.5-1.5B-Instruct` v7 + CTX 重跑合计 110 条有效 rollout，出现 20 个 stable 违反检查项（含行为层失败），分布在 7 个任务、4 个维度。`final-test-v1` baseline 又得到 26 个 stable（20 个 valid、6 个来自 U-FT10/11 缺陷），任务成功仅 2/11；这改变了“1.5B 也没有 stable”的旧判断，但没有证明训练增益。

### 4.2 条件式建议

1. **CTX 已完成修复**：fixture 缩至 25 行/文件 + `max_model_len=8192` 后，CTX 两任务各 10 次重跑 20/20 有效、0 个 400 error。CTX-BASE 10/10 成功，CTX-HARD 出现 2 个 stable；不能把 400 error 写成 stable=0 或 stable 违反。
2. **路线 B 有 stable 依据**：`constraint_count` 10 项、`context_length` 2 项、`tool_parameters` 3 项、`conflict` 5 项达到 `>=6/10`，其中 `CTX-HARD`、`TOOL-HARD`、`CONFLICT-WEAK/STRONG` 是行为层 stable 失败。二十项分布在 7 个任务上，不是单任务夹具问题。
3. **四组对比暂不启动**：`final-test-v1` 的 A 组 baseline 已有数据，但 U-FT10/11 使 test 不干净；B 组系统侧方案（constrained decoding v4）未跑通，只能退回 prompt 层；C/D 组需要尚未生成的 train split 和真实 SFT。先作废升 `final-test-v2` 或显式排除 U-FT10/11，再生成 train split 和四组 runner；没有这些条件不跑 SFT，也不写训练增益。
4. **constrained decoding 的两种结果**：若把格式违反压到 0，写“系统侧方案足够，格式层不需要训练”；若仍有翻转，写“多轮 Agent 下 token 级约束仍受采样非确定性影响”。两种结论都只限定在输出格式层，不外推到工具行为。
5. **不建议直接扩到 100–200 个训练任务**：先修正 final test 的有效性，再在这个 9–11 任务 test 上验证“系统侧/训练侧是否有增益”；若增益存在，再按同一维度分布扩到 100–200 个训练任务。没有四组结果前扩数据只会增加夹具成本。

### 4.3 新 test 冻结方案

- 当前 pilot test 继续标注为“调参用，不作最终对比”；其哈希只证明文件未变，不证明预注册。
- 最终 test `final-test-v1` 已冻结：11 个任务、fixture seed `95001`–`95011`、SHA-256 `ef4d3113...653af7`；与 `TASK_SPECS` / `TUNING_TASK_SPECS` 的任务 ID 和 seed 严格不重叠。
- v1 的 baseline 已完成 110 条，但 U-FT10/11 的 prompt/fixture 不一致使 6 个 stable 无效；因此 v1 不能直接作为四组最终 test。
- 若选择修正：作废 v1、升 `final-test-v2`（修正 U-FT10/11 的 prompt 路径/行号/token），重新冻结并重跑 baseline；若选择保留 v1：四组统计必须排除这两个任务，test 降级为 9 任务，且报告中保留原始 26 个 stable 与 20 个 valid stable 的差异。

### 4.4 建议

**建议先修正 final test，再谈四组对比**。v7 + CTX 重跑已在 1.5B 上得到 20 个 stable，且包含行为层失败；`final-test-v1` baseline 的有效部分是 20 个 stable、7/11 个任务，数字门禁满足。但 U-FT10/11 的 prompt/fixture 不一致会把夹具错误算成模型差异，且 train split 尚未生成、系统侧 prompt 变体尚未预注册。建议：

1. 作废 `final-test-v1`，修正 U-FT10/11 后冻结 `final-test-v2`，重跑 110 条 baseline；
2. 生成与 test 不重叠的 train split，先做小规模 SFT smoke，再做四组；
3. 系统侧先做 prompt 层自检，在 dev 上选型；constrained decoding 只有真正跑通后才加入；
4. 四组结果出来前不写训练增益，不把 26 个 stable 直接写进简历。

简历价值上，路线 A 仍可写：完整 trace 可观测性、违反归因与稳定性门禁、可控冲突实验、方向 C 手工验证、constrained decoding 对照、Kaggle 训练管线储备；这些都比“为训练而训练”的数字更可辩护。路线 B 只有在真实 stable 违反和四组对照都跑完后才值得写训练增益。
