# 简历措辞：终端 Coding Agent

**终端 Coding Agent：长任务约束遵循与后训练可靠性验证** | 个人项目
github.com/autumnieave/lite-coding-agent

项目概述：针对长任务中上下文压缩静默丢失约束、且“约束在上下文≠模型遵守”的痛点，从零构建终端 Coding Agent 实验平台，按 Harness 分层验证（约束→工具→评测→训练→决策）组织，核心方法论为“存在≠生效”——每层只证明本层能证明的事，不跳层外推。验证规模：409 任务池、3,272 条 baseline rollout、450 对配对统计。

技术栈：后训练（SFT/QLoRA/Loss Masking）· 评测（Trace 归因/pass^10 / 稳定通过率/McNemar/预注册门槛）· Agent（Harness Engineering/Guardrails/Context Engineering）· 工程（vLLM/pytest 857/CI）

约束层（Guardrails + Context Engineering）：原文在 ≠ 行为生效。自研约束独立存储 + 双路注入 + 约束补录，压力档（deepseek-flash）违规 19→5 次、原文保留 69%→95%；但 Qwen2.5-7B 默认注入下 64 条约束中行为探针仅 23 条合规（小样本），定位补录仅校验 ID、未校验正文——系统侧可保证原文与补录完整性，行为生效需训练侧补。

工具层（Harness Engineering）：能调用 ≠ 调用可靠。从零实现 Tool-Calling Agent Loop + 6 工具（Pydantic 参数校验 + 路径越界拦截），补幂等键防重复副作用、会话 checkpoint 支持 kill 后恢复。

评测层（Trace 归因）：模型能跑 ≠ 结果可信。全链路 Trace 归因发现 temperature=0 下仍有 3.57% 判定翻转率（560 配对观测），引入 pass^10 / 稳定通过率口径；在去重叠的 45 个任务上，SFT 提升 +50.3pp（McNemar p<1e-13），重叠/非重叠增益一致，排除逐字记忆。

训练层（SFT 变量归因）：能训 ≠ 训对了。7B QLoRA SFT 首跑全灭 → Trace 定位模板不一致 → 修复后 30/30（pipeline 修复，非模型能力增益）；消融证明 full-loss 致长上下文任务通过数 0/10、Loss Masking 恢复 10/10。API vs 本地：严格契约下 99.8% vs 90.9%（去 fence 后对齐，差异主要来自输出格式）。增益具条件性（tagged 提升、untagged 反降），不作泛化声称。

决策层（GRPO 预检）：能启动 ≠ 该启动。GRPO 预检——45 任务 × 8 rollout，44/45 饱和、存在部分成功/中间态信号的任务为 0，按预注册判据（中间态为 0 则不启动），SFT 已覆盖这批任务、RL 无梯度信号，因此不启动全量 RL。
