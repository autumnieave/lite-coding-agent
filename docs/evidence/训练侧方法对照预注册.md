# 训练侧方法对照预注册（train-v4）

## 1. 目的与边界

本阶段把 `training/` 作为项目主线之一：先扩到可做方法级对照的数据量，再用单变量
实验验证 loss masking、数据配比和 DPO。89 条 train-v2 数据只用于管线验证，不能作为
方法结论。每个实验只改变一个变量，其他训练配置、行为 held-out 和采样配置保持一致。

本轮不跑 GRPO。原因不是“GRPO 不重要”，而是当前 reward 尚未经过独立 rollout 验证，
且重复调用、拿到答案后继续调用、`within_steps` 失败等行为惩罚还没有被证明不会诱发
reward hacking。DPO 不需要独立 reward model，因此先作为偏好优化对照。

## 2. 数据：train-v4

冻结产物：`private/sft_data_v4/`。

| 项目 | train | val |
| --- | ---: | ---: |
| DeepSeek teacher 轨迹 | 90 | 34 |
| xLAM 严格 grep schema 映射 + 本地真实执行 | 92 | 24 |
| 确定性 oracle 轨迹 + 本地真实执行 | 198 | 22 |
| **合计** | **380** | **80** |

类别分布：

| 类别 | train | val |
| --- | ---: | ---: |
| BASE | 23 | 7 |
| HARD | 77 | 21 |
| CTX | 47 | 8 |
| TOOL | 144 | 33 |
| CONFLICT | 89 | 11 |

数据边界：

- xLAM 原始 60,000 行，只有 116 行能严格映射到本地六工具中的 `grep`；其余 59,884 行
  因工具名或参数不可映射被拒绝，不做硬改。
- xLAM 样本的 tool result 来自本地真实 registry 执行，不是公开数据里的原始结果；报告
  必须写“schema-mapped + local re-execution”。
- ToolACE 的工具生态与本地六工具不兼容，没有混入 train-v4。
- train-v4 与 `final-test-v2` 的任务 ID、fixture seed 均不重叠；train/val 行 ID 不重叠。
- train-v4 冻结 SHA-256：
  - train: `ce52295b28e533b1dc40ae1466d5749c14c7d029c0b4b732d41054745fbda7b8`
  - val: `18007e4f1b1c2ffd64984918563eefd190f759445dcf80be46e663b94fb20b77`
  - combined: `c8849296271ffc1d24f736961fc365fc7853e8dc2389917b9048777d52f2f745`
- Qwen tokenizer render gate 在每次 Kaggle 训练前执行；必须满足 tool-call 可渲染、
  tool schema 出现在训练文本中、无结构错误。超过 3072 token 的样本由训练脚本显式丢弃
  并写入 manifest，不能静默当成全部训练成功。

## 3. 共用训练配置

- 基座：`Qwen/Qwen2.5-7B-Instruct`
- 量化：NF4 + double quant，compute dtype `float16`
- LoRA：`r=64`，`alpha=128`，dropout `0.05`，`all-linear`
- batch：`per_device_train_batch_size=1`，gradient accumulation `8`
- 序列长度：`3072`
- optimizer：`paged_adamw_8bit`
- Liger fused CE + 非重入 gradient checkpointing
- 2 epochs，学习率 `2e-4`（除非该实验显式改变）
- 固定 seed：第一轮 `20261019`；基线波动范围用 `20261020`，成本允许时再加 `20261021`

训练与推理必须使用同一套 Qwen chat template 和 `tools=` schema。模板不一致会使训练
渲染 token 数与推理渲染严重偏离，这种运行不能进入方法比较。

## 4. 行为 held-out

行为评测不使用 train-v4 的 record-level val。固定沿用 train-v2 的 6 个全链路任务：

```text
U-TR-A-C1-HARD
U-TR-B-CHECK-BASE
U-TR-B-C1-BASE
U-TR-B-CTX-HARD
U-TR-B-TOOL-HARD
U-TR-B-CONFLICT-WEAK
```

每个任务 10 次 rollout，`temperature=0.0`、`top_p=None`、`seed=20261019`。报告：

- BASE/HARD 分拆的 `task_success`
- `valid stable`（剔除 `within_steps=false` 后仍达到 `>=6/10` 的检查项）
- `within_steps` 失败数
- 工具调用成功率

## 5. 对照设计

### 5.1 扩数据后 SFT 基线

**假设**：89 条数据只够验证管线；380 条 train-v4 能提供更稳定的方法比较参照系。

**变量**：无。train-v4 + 上节共用配置。

**报告**：至少 2 个 seed 的训练结果和行为 held-out；如果 byte-level 不可重复，
报告实际差异和 `model_version`/环境信息，不伪造置信区间。

**判定**：基线是后续所有对照的参照。没有跨 seed 波动范围，不宣称小差异显著。

### 5.2 Loss masking

**假设**：全序列 loss 会让模型学习复述 system/user/tool response；assistant-only loss
只监督 assistant tool-call JSON 和最终回答，应减少“复述观察结果”的行为。

**变量**：`full` vs `assistant_only`。数据、seed、lr、rank、epoch、held-out 全部不变。

**决策**：tool response 在 assistant-only 中 mask；不 mask assistant tool call 本身。

**判定**：如果 held-out 差异落在基线 seed 波动范围内，写“扩数据后 loss masking 差异
不显著”，不写“有效”。如果 `within_steps` 或格式检查出现退化，如实记录副作用。

### 5.3 数据配比

**假设**：纯约束/工具数据会挤压通用能力；混入约 15% 通用对话可降低灾难性遗忘。

**变量**：train-v4 纯约束数据 vs train-v4 + 15% Dolly 通用数据。其他配置不变。

**通用数据**：`databricks/databricks-dolly-15k`，CC-BY-SA-3.0，固定 seed 抽样 67 条，
追加到 380 条后共 447 条，实际比例 `14.99%`。

**判定**：同时报告 BASE/HARD、`task_success`、`valid stable`、`within_steps`。如果
BASE 更稳但 HARD 下降，写权衡，不写单边胜利。

### 5.4 DPO

**假设**：在 SFT 策略上，用 rejected 轨迹和显式格式负样本做偏好优化，可减少格式/协议
失败；但合成负样本占比高，不能预期大幅提升任务能力。

**数据**：`private/dpo_v1/`，92 对，68 train / 24 val，全部为明确标注的 synthetic
negative。构造时排除 6 个行为 held-out task ID（val 80 行中排除 34 行），并排除与
SFT train prompt 重叠的 5 条自然 rejected；排除后自然 rejected 为 0 条。因此 DPO
只验证合成格式偏好是否可学，不能声称覆盖真实错误分布。

**变量**：SFT vs SFT+DPO。DPO 从同一个 SFT adapter 初始化；reference 为 adapter 关闭
的 SFT 前基座；`beta=0.1`；LoRA；其余训练配置与 SFT 对齐。

**报告**：偏好对数量、beta、DPO loss、optimizer step、SFT 与 SFT+DPO 的 held-out
差异。

**判定**：合成负样本只证明格式偏好是否可学，不证明真实错误分布被覆盖；如果 DPO 只在
BASE 格式项上变化、HARD 不变，按此边界报告。

### 5.5 lr/rank（可选）

只有在已有明确假设且 GPU 配额允许时运行，不做无假设扫参：

- `lr=1e-4, r=16`
- `lr=1e-4, r=64`
- `lr=2e-4, r=16`
- `lr=2e-4, r=64`

假设分别是“小数据下 lr 2e-4 更快过拟合”和“r=64 更容易记住训练集”。报告 held-out，
不只看 train_loss；不为寻找“最优超参”而扩大搜索。

### 5.6 DRIFT-Bench（可选）

如果环境可运行，只做一次外部锚定，2–3 个领域、30–60 任务，报告随 horizon 的趋势；
环境不通就写“未跑通”，不反复调试。

## 6. 结果报告规则

- 每个数值必须能追溯到 Kaggle 输出或本地冻结文件；不写“大致”“估计”冒充实测。
- 训练和评测分开进程执行，adapter 保存后检查文件非空；0 字节 adapter 不得进入 held-out。
- 所有对照按 BASE/HARD 分拆；总体数字不能替代分拆。
- 跨 seed 差异小于波动范围时，不宣称方法有效。
- 公开数据、教师数据、确定性 oracle 数据在报告中分开标注来源。
- 任一实验失败写 `error_kind`、失败阶段和实际 rollout 数；不把基础设施失败写成模型能力结论。
