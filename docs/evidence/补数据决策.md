# 阶段 0.0a 补数据决策与 train-v5 冻结

> 输入审计：`docs/evidence/数据多样性审计.md`
> 冻结目录：`private/sft_data_v5/`
> 教师模型：`deepseek-flash`（temperature=0.0，top_p=None，seed=20261019）
> 性质：只补已确认的分布缺口；未修改 train-v4、final-test-v2 或 `core/`。

## 0. 结论

- 阶段 0.0a 判定为**补数据**，但先诊断 CTX-HARD 超长根因，再按缺口扩展。
- CTX-HARD 根因是 **fixture 太长**，不是教师轨迹太长，也不是 Qwen `tools=` 渲染额外膨胀。
- train-v5 最终 **468 train / 84 val**，全部通过 Qwen tokenizer 3072 门禁和 assistant-only mask 校验。
- train-v5 的 CTX-HARD 有效 **37 条**（目标 30–40）；long context 有效 **37 条**；train/val task ID 与 final-test-v2 无重叠。
- `context_recall` 教师通过率 **44/114 = 38.60%**，低于 50%；按边界要求记录“该类教师数据供给偏弱”，未继续硬凑，也未放松门禁。
- 58 条 `CODE=` 前缀轨迹按既定规则过滤，最终 CTX-HARD 训练样本中 `CODE=` 前缀泄漏为 **0**。

## 1. CTX-HARD 超长根因

逐条 token 分解见 `docs/evidence/CTX_HARD_token审计.md` 与 `docs/evidence/ctx_hard_token_audit.json`。

| 样本 | 总 token | fixture token | fixture 占比 | `tools=` 模板 | system/user | tool-call JSON |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `U-TR4-00-CTX-HARD` | 6444 | 4511 | 70.00% | 1260 | 259 | 540 |
| `U-TR-A-CTX-HARD:rollout7` | 6217 | 4260 | 68.52% | 1260 | 284 | 607 |
| `U-TR-B-CTX-HARD:rollout0` | 6900 | 4783 | 69.32% | 1260 | 284 | 841 |
| BASE 对照 | 1567 | 10 | 0.64% | 1260 | 214 | 61 |

**判定：fixture 太长。**

- train-v4 的 CTX-HARD 使用 10 文件 × 25 行 filler，fixture 本身约 4511 token，占超长轨迹约 70%。
- 教师轨迹约 10 次工具调用，不是超长主因。
- `tools=` 固定增加约 1260 token，把已接近上限的 fixture 推过 3072。
- 训练渲染与推理直接调用 `apply_chat_template(..., tools=...)` 的 token 数一致；不是训练模板单独膨胀。
- 修复只作用于 train-v5 新任务：保留 8–10 个文件、多轮读取和最终 CODE 回忆，把每文件 filler 缩短为 4 行。
- 未修改 final-test-v2 fixture，未把全局 `max_seq_length` 提到 4096。

## 6. 边界

- `context_recall` 教师通过率低于 50%，只补到目标区间，没有继续增加同模板样本硬凑总量。
- `CODE=` 前缀轨迹只做过滤，不放宽 `answer_exact` 检查。
- 没有修改 `core/loop.py`、`compaction.py`、`constraints.py`。
- SFT 增益结论必须以 train-v5 assistant-only 的真实 held-out 重跑为准；不复用 train-v4 full-loss 或 assistant-only 的数字。

## 7. train-v5 assistant-only SFT 验证

Kaggle kernel `autumnsq/lite-agent-method-assistant-train-v5` 已完成，Tesla T4 14.56 GB，总时长 8657.7 s，训练 6361.7 s，optimizer steps=116，adapter 645,975,704 bytes。

| 条件 | task_success | BASE | HARD | 工具结果 | stable checks |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 40/60 = 66.67% | 20/30 | 20/30 | 160/180 = 88.89% | 4 |
| train-v5 assistant-only | 60/60 = 100% | 30/30 | 30/30 | 190/190 = 100% | 0 |

按 10 次 rollout 中至少 6 次成功记为 pass^k，baseline 为 **4/6 个任务**稳定通过，SFT 为 **6/6 个任务**稳定通过。

**CTX-HARD 口径**：本轮 baseline 10/10、SFT 10/10，不是 0/10 → 非 0。历史 0/10 属于 train-v4 **full-loss**；train-v4 assistant-only 已经是 10/10。因此本轮只能证明“补数据后 assistant-only 未退化”，不能证明补数据修复了 assistant-only 的 CTX-HARD，也不能把 full-loss 的 0/10 单独归因于数据缺口。完整记录见 `docs/evidence/训练管线验证.md` 的 10.7 节。
