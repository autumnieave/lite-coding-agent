# 补录修复 tagged 模式重测（train-v6，故障注入）

**日期**：2026-10-28
**定位**：方向性证据，不做 McNemar / Bootstrap，不写“统计显著”。
**一句话结论**：在 tagged 模式、强制 ID-only summary 的故障注入下，补录修复把语义保留
从 `0/64` 提升到 `64/64`，行为合规从 `17/64` 提升到 `64/64`，违反从 `31/64` 降到
`0/64`。这验证了 ID+正文双重校验的补录路径，不等同于自然摘要或 untagged 模式的效果。

## 1. 实验口径

旧版 32 条实验的自然 tagged 摘要正文原本都在，修复不会触发；要验证修复效果，必须
让 tagged 路径收到“ID 在、正文丢”的摘要。本轮采用确定性故障注入：摘要固定写成
`关键约束：- <ID>`，只保留约束代号，不包含正文。

| 项目 | 配置 |
| --- | --- |
| 任务 | 32 个训练重叠的中间态任务，BASE 12 / HARD 8 / TOOL 12；tasks SHA-256 `e4b94104...8d736` |
| 探针 | 32 任务 × 2 类约束 = 64 条 tagged 探针/条件 |
| 基座 | Qwen2.5-7B-Instruct，4-bit NF4 |
| adapter | train-v6，SHA-256 `37928a28...a4b96` |
| 修复前 | `LegacyConstraintStore` 复现旧行为：只校验 ID，不校验正文 |
| 修复后 | 当前 `ConstraintStore.verify(..., require_body=True)`：ID + 正文双重校验 |
| 运行 | Kaggle Tesla T4 14.56GB，greedy，1 rollout |
| kernel | `autumnsq/lite-agent-replenish-tagged-64`，675.4 秒 |
| 原始数据 | `private/kaggle_pull_replenish_tagged64/replenish_tagged64/` |

untagged 历史数据没有改动；它是“不创建 ConstraintStore、系统不管约束”的对照组。
本轮只跑 tagged，不代表 untagged 也会有补录收益。

### 判定与可比性

- 修复前后使用同一 `retention_for`、`classify_probe` 和 `build_probe_messages`。
- tagged 与 untagged 的语义判定、违规判定和强制选择探针相同；差异是 tagged 用
  `[CONSTRAINT] 代号` 并创建 `ConstraintStore`，untagged 用普通列表且无 store。
  两者声明都在 user message，不是 system prompt 最前面。
- 修复前 17/64 的失败是混合的：行为规则 `16` 合规 / `16` 未分类
  (`confirmed` / `deferred_tool`)，信息约束 `1` 合规 / `31` 违反
  (`executed_violation`)。
- 旧自然摘要 train-v6 的 `53/64` 是 tagged + untagged 合计（untagged `28/32`、
  自然 tagged `25/32`），不是 untagged-only；与本次 tagged 故障注入 `17/64`
  不可直接比较。

## 3. 判定

补录缺陷是这批 tagged 故障注入下 31 条信息约束违反的直接原因：修复前摘要只剩 ID，
旧实现认为约束仍在，不触发补录；修复后正文被补回，信息约束的目标路径和行为规则的
禁止语义都恢复，64 条行为探针全部转为合规。在这个故障注入内对照里，ID+正文校验
完整恢复了系统侧补录链。

同一语义丢失在类型上分裂成两种失败模式：行为规则 16 条只读/未分类（模型变保守、
不敢执行），信息约束 31 条越界执行（模型不知道边界）——不是单一退化解。

这支持“补录修复在 tagged 路径上可达且有效”，不支持“补录修复能改善 untagged 行为”，
也不支持“SFT 单独解决了约束遵守”。untagged 模式不创建 ConstraintStore，补录路径
不可达；自然摘要下的 tagged 结果仍需单独测量。

## 4. 边界

- tagged 模式、32 任务 × 2 约束 = 64 条，每组 1 rollout；
- 强制 ID-only summary 是故障注入，不是自然摘要质量实验；
- 未做显著性检验，不能外推到 clean held-out 或未见任务族；
- untagged 历史数据未改，作为“系统不管约束”的对照；
- 修复前使用行为等价的旧校验分支，修复后使用当前 ID+正文校验。
