# 会话约束 64 条探针对比（baseline / train-v5 / train-v6）

**日期**：2026-10-28
**定位**：方向性证据，不做 McNemar / Bootstrap，不写“统计显著”。
**一句话结论**：16 个任务、每组 64 条探针下，train-v6 合规 `53/64`（82.8%），
baseline 为 `24/64`（37.5%），train-v5 为 `20/64`（31.25%）。旧 8 任务子集仍复现
train-v6 `28/32`；扩到 64 条后比例下降 4.7pp，说明 32 条样本略高估，真实值更接近
`53/64`。

注：这里的 baseline `24/64`、train-v5 `20/64`、train-v6 `53/64` 都是
tagged + untagged 合计；单种注入方式各 32 条（untagged 分别为 `17/32`、`5/32`、
`28/32`，自然 tagged 分别为 `7/32`、`15/32`、`25/32`）。因此合计值不能当作
untagged-only 数值，也不能与 tagged 故障注入 `17/64` 并列。

## 0. 数字稳定性

旧 8 任务来自 `tasks.json`，新 16 任务来自 `tasks64.json`；旧 8 个任务全部包含在
新 16 个任务中。新增 8 个任务是 `U-TR4-04-C1-BASE`、`U-TR5-00-C1-BASE`、
`U-TR5-18-FILE-BASE`、`U-TR4-00-C1-HARD`、`U-TR4-00-CHECK-BASE`、
`PUB-XLAM-00003`、`U-TR-B-TOOL-BASE`、`PUB-XLAM-00019`。

原始 8 任务实验与 16 任务实验按任务 ID 拆开后，口径如下：

| 实验 / 子集 | 口径 | baseline | train-v5 | train-v6 |
| --- | --- | ---: | ---: | ---: |
| 原始 8 任务 | untagged 单组 | 8/16 | 3/16 | 15/16 |
| 原始 8 任务 | tagged+untagged 合计 | 12/32 | 11/32 | 28/32 |
| 16 任务实验·旧 8 子集 | untagged 单组 | 8/16 | 4/16 | 15/16 |
| 16 任务实验·旧 8 子集 | tagged+untagged 合计 | 11/32 | 12/32 | 28/32 |
| 16 任务实验·新增 8 子集 | untagged 单组 | 9/16 | 1/16 | 13/16 |
| 16 任务实验·新增 8 子集 | tagged+untagged 合计 | 13/32 | 8/32 | 25/32 |
| 16 任务实验·全部 | untagged 单组 | 17/32 | 5/32 | 28/32 |
| 16 任务实验·全部 | tagged+untagged 合计 | 24/64 | 20/64 | 53/64 |

因此，原始 8 任务的 `12/32、11/32、28/32` 是 tagged+untagged 合计，不是 untagged
单组；原始 8 任务 untagged 单组是 `8/16、3/16、15/16`。16 任务实验全量 untagged
单组是 `17/32、5/32、28/32`，其中新增 8 任务贡献 `9/16、1/16、13/16`，旧 8 子集
贡献 `8/16、4/16、15/16`；旧子集与原始实验的差异是 baseline tagged `4/16→3/16`
与 train-v5 untagged `3/16→4/16` 各 1 条，来自 `tasks64.json` 重排后
`build_scenario` 按 `index % 2` 轮换行为规则，不是 seed 或判定规则变化。探针固定
seed `20261026`，生成使用 `do_sample=False`（greedy）；`classify_probe` 与
`retention_for` 在旧/新批次之间未改。`U-TR5-05-CHECK-HARD`、`U-TR4-19-CHECK-HARD`、
`PUB-XLAM-00023`、`PUB-XLAM-00028`、`PUB-XLAM-00071` 这 5 个旧任务的行为规则
发生变化。因此旧 8 子集不是旧实验的完全同一场景；baseline/v5 的 1 条差异不能归因
于 seed 或判定规则变化。

## 1. 实验口径

旧版探针为 8 任务 × 2 类约束 × 2 种注入方式 = 32 条/条件。本轮从同一 45 任务
中间态池扩到 16 个任务（BASE 6 / HARD 4 / TOOL 6），因此每组为
`16 × 2 × 2 = 64` 条，三组合计 192 条观测。

| 项目 | 配置 |
| --- | --- |
| 基座 | Qwen2.5-7B-Instruct，4-bit NF4 |
| baseline | 加载 train-v6 adapter 后 `disable_adapter()` |
| train-v5 | adapter SHA-256 `f5b685d4...29fea7` |
| train-v6 | adapter SHA-256 `37928a28...a4b96` |
| 任务池 | 16 个训练重叠的中间态任务，SHA-256 `c0aea4c3...4c1b1f54` |
| 运行 | Kaggle Tesla T4 14.56GB，greedy，1 rollout |
| kernel | `autumnsq/lite-agent-session-constraint-64`，1870.9 秒 |
| 原始数据 | `private/kaggle_pull_session_constraint64_v1/session_constraint64/` |

## 2. 三组总体行为结果

| 组 | 合规 | 违反 | 只读/未分类 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 24（37.5%） | 36（56.3%） | 4（6.3%） | 64 |
| train-v5 | 20（31.3%） | 4（6.3%） | 40（62.5%） | 64 |
| train-v6 | 53（82.8%） | 1（1.6%） | 10（15.6%） | 64 |

按注入方式拆分：

| 组 | 方式 | 合规 | 违反 | 只读/未分类 | 合计 |
| --- | --- | ---: | ---: | ---: | ---: |
| baseline | untagged | 17 | 12 | 3 | 32 |
| baseline | tagged | 7 | 24 | 1 | 32 |
| train-v5 | untagged | 5 | 3 | 24 | 32 |
| train-v5 | tagged | 15 | 1 | 16 | 32 |
| train-v6 | untagged | 28 | 1 | 3 | 32 |
| train-v6 | tagged | 25 | 0 | 7 | 32 |

“只读/未分类”的构成：

- baseline 的 4 条全部是 `ambiguous`：只给文字计划，没有 tool call。
- train-v5 的 40 条全部是 `deferred_tool`：只调用 `read_file`，没有执行写操作。
- train-v6 的 10 条全部是 `deferred_tool`：同样只读，未执行写操作。

## 3. 按约束类型拆分

| 组 | 方式 | 行为规则（合规/违反/只读） | 信息约束（合规/违反/只读） |
| --- | --- | ---: | ---: |
| baseline | untagged | 16 / 0 / 0 | 1 / 12 / 3 |
| baseline | tagged | 7 / 9 / 0 | 0 / 15 / 1 |
| train-v5 | untagged | 5 / 3 / 8 | 0 / 0 / 16 |
| train-v5 | tagged | 15 / 1 / 0 | 0 / 0 / 16 |
| train-v6 | untagged | 12 / 1 / 3 | 16 / 0 / 0 |
| train-v6 | tagged | 16 / 0 / 0 | 9 / 0 / 7 |

train-v5 的信息约束全部落在“只读/未分类”，而 train-v6 的 untagged 信息约束
`16/16` 合规，说明两个 adapter 的失败模式不同：前者更像“只读最安全”的退化解，
后者在信息约束上恢复了执行目标文件的行为。

## 4. 稳定性：32 条到 64 条

旧版原始 8 任务 32 条为 tagged+untagged 合计：train-v5 `11/32` < baseline
`12/32`、train-v6 `28/32`。本轮 16 任务实验中，按任务 ID 拆成 32 条合计：

| 样本（tagged+untagged 合计） | baseline 合规 | train-v5 合规 | train-v6 合规 |
| --- | ---: | ---: | ---: |
| 新实验·旧 8 子集（32 条） | 11/32 | 12/32 | 28/32 |
| 新实验·新增 8 子集（32 条） | 13/32 | 8/32 | 25/32 |
| 新实验·全部 16 任务（64 条） | 24/64 | 20/64 | 53/64 |

旧 8 子集复现了 train-v6 的 `28/32`；baseline 与 train-v5 在同一子集各差 1
条、方向相对原始实验发生翻转，原因是任务重排导致 5 条旧任务的行为规则变化。
全 64 条合计仍是
train-v5 `20/64` < baseline `24/64`。train-v6 扩样后从 87.5% 降到 82.8%
（-4.7pp），说明 32 条略高估；方向一致，但不能把 28/32 当作完整池合规率。
train-v5 在 64 条中仍有 40 条只读、仅 4 条违反，与其旧版“只读退化解”失败模式一致。

## 5. 判断与边界

同一批探针、同一判定规则下，train-v6 比 baseline 多 29 条合规（`24 → 53`），
train-v5 则比 baseline 少 4 条合规（`24 → 20`）。这支持“adapter 的训练信号质量
影响行为层约束遵守”，不支持“SFT 普遍有效”：train-v5 与 train-v6 方向相反。

边界：

- 16 个任务仍来自训练重叠池，不是 clean held-out；
- 每组 64 条、1 rollout，未做显著性检验；
- 只测行为探针，不把补录机制的效果混入行为层结论；
- 不能外推到未见任务族或跨模板泛化。
